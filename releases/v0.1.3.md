FrankMDFast 0.1.3 fixes sync scrolling in the preview and system-file watching on macOS.

## Fixed

- With scroll sync on, scrolling the preview snapped back to where it started: the preview moved
  the editor, and the editor reported that move back as a user scroll one frame late, pulling the
  preview with it. Programmatic sync scrolls no longer echo back, and plain scrolls (and opening
  a note at a line) still move the preview (#7, contributed by @Okaada).
- Sync scrolling now tracks the position *inside* long soft-wrapped lines instead of holding
  still and then jumping a whole line (#7).
- macOS: watching the Omarchy theme, language and fontconfig files through a symlinked path
  (FSEvents reports the real `/private/...` spelling) never fired; both spellings now match,
  with a regression test pinning the behavior (#6, contributed by @Okaada).

## Changed

- The macOS CI job now runs the full test suite (Linux and macOS both gate every push; Windows
  builds and runs the Windows-only path and vault tests).
